# 案例 9：定长内存池与消息队列 - 项目需求文档

## 1. 文档信息

- 项目性质：无硬件 C 语言综合项目
- 小组人数：6 人
- 推荐周期：3～5 天
- 语言标准：ISO C17
- 构建方式：Makefile 或 CMake
- 运行平台：Linux、macOS、Windows + MinGW/WSL

## 2. 通用工程约束

- 必须采用多文件结构，公开接口放在头文件中；
- 启用 `-Wall -Wextra -Wconversion -Wshadow -Wpedantic`；
- 测试阶段启用 AddressSanitizer 和 UndefinedBehaviorSanitizer；
- 禁止 `gets`、无长度限制的字符串写入及未检查的数组访问；
- 所有动态内存、文件和其他资源都要有清晰的释放路径；
- 错误信息必须指出模块、原因和必要的上下文；
- 核心模块不得依赖大面积全局可变状态；
- Git 提交应能反映六位成员的持续贡献。

## 3. 项目目标

实现无需逐块malloc的固定内存池，并用池中节点构建ECU事件消息队列。

## 4. 项目范围

### 4.1 必做功能

1. 配置块大小和块数量；
2. 分配、释放和池耗尽处理；
3. 检测重复释放和池外地址；
4. 统计在用、峰值、失败次数；
5. 基于池构建FIFO消息队列；
6. 退出时检查未释放块；

### 4.2 不在本期范围

- 不连接真实车辆、ECU 或采集板卡；
- 不要求图形界面，命令行即可；
- 不要求实现完整商业标准，只实现文档明确的子集；
- 不允许用 Python、C++ 替代核心 C 模块。

## 5. 建议模块

- `memory_pool`
- `free_list`
- `pool_guard`
- `message`
- `message_queue`
- `stress_stats`

每个模块应提供职责说明、公开 API、错误码、所有权规则及线程/重入假设。跨模块传递指针时必须说明对象由谁创建、由谁释放、有效期到何时。

## 6. 六人分工

1. 组长/架构：内存布局和集成；
2. 内存池：初始化、分配、销毁；
3. 安全检查：地址、位图、重复释放；
4. 消息对象：负载和生命周期；
5. 队列：入队、出队、清空；
6. 测试工程：随机压力、Sanitizer、报告；

### 6.1 协作规则

- 六人均须提交实际代码、测试和文档；
- 每位成员至少维护一个 `.c/.h` 模块；
- 接口由组内评审后冻结，修改需记录原因和影响；
- 合并前必须由非作者完成代码评审；
- 集成问题由相关模块责任人共同定位。

## 7. 输入、输出与错误处理

- 输入可来自配置文件、脚本、CSV、二进制文件或命令行；
- 文件格式必须在 `docs/file_format.md` 中定义并给出示例；
- 所有输入须检查长度、范围、格式和重复项；
- 输出至少包含正常结果、错误信息和可追踪日志；
- 程序退出码：0 表示成功，非 0 表示失败；
- 文件打开、内存分配和解析失败均不得导致资源泄漏；
- 不可信长度参与分配或地址计算前必须检查溢出。

## 8. 必测场景

1. 分配至耗尽并恢复；
2. 重复释放、池外地址、NULL释放；
3. 空队列、单节点、多节点FIFO；
4. 队列未清空时销毁；
5. 10万次随机入队出队；

测试至少分为正常、边界、异常、故障注入和长时间运行五类。每个缺陷修复后必须增加回归测试。

## 10. 验收标准

1. 初始化后不逐块malloc；
2. 非法释放可检测且不破坏空闲链表；
3. 压力测试后全部块可回收；
4. 无越界、双重释放和泄漏；

此外必须满足：

- 一条命令完成构建，一条命令执行全部测试；
- Debug 构建无编译警告；
- 正常退出及错误退出均无已知资源泄漏；
- README 中的步骤可在干净环境复现；
- 六位成员均能说明整体架构、接口和本人贡献。

## 11. 最终交付物

1. `src/`、`include/` 下的完整 C 源码；
2. Makefile 或 CMakeLists.txt；
3. README 与运行示例；
4. 需求追踪矩阵；
5. 架构、接口、数据结构和文件格式文档；
6. 单元测试、集成测试和端到端测试；
7. 测试数据、预期结果与测试报告；
8. Sanitizer 执行结果；
9. Git 贡献记录和代码评审记录；
10. 10～15 分钟演示及项目复盘。

## 12. 教师答辩检查点

- 为什么采用当前数据结构和模块边界？
- 指针参数的所有权与生命周期是什么？
- 最危险的越界、泄漏或整数溢出位置在哪里？
- 输入损坏时程序如何进入可控失败状态？
- 如何证明核心功能满足需求？
- 哪些测试由本人编写，曾发现什么缺陷？
- 若替换成真实硬件接口，哪些模块保持不变？
